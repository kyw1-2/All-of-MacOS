## New architecture

- **Display identity:** Each floating card retains its source NSScreen ID. Cursor motion does not teleport old cards to another monitor. A topology-change notification re-evaluates the screen when a monitor is unplugged, and the coordinator reflows only the cards on that display.
- **Deterministic screen geometry:** `QuickAccessGeometry` selects a screen and calculates a bounded target frame using that screen's visible rect. Works with negative origins, portrait displays, four corners, 1–3 cards and even constrained screen rectangles.
- **Native drag and local receiver:** The Quick Access thumbnail uses `NSDraggingItem` with an `NSURL` file writer and receives `NSDraggingSource.draggingSession(endedAt:operation:)` to distinguish successful drop from cancellation. The built-in `Quick Access Drag Diagnostics…` window exposes a real AppKit receiver that accepts standard file URL drops. It compares the received PNG bytes with the temporary source; the example is never uploaded or sent.
- **Permission recovery:** Settings refreshes the four publicly queryable permission categories every five seconds while visible and on app activation. Permission transitions display a non-destructive explanation; Screen Recording/Input Monitoring changes may require relaunch. Accessibility monitor recovery is already handled separately.
- **Source protection:** The fixture is created in a unique temporary folder and removed when the diagnostic window closes; actual capture history/personal files are never deleted by the diagnostic test.

## Validation tiers

| Scenario | Verification method | Claim boundary |
| --- | --- | --- |
| Drag file writer | XCTest native `NSURL` ↔ NSPasteboard round trip, bad URLs rejected | Proves standard local file URL format, not acceptance by every app |
| Native source → AppKit receiver | Open Capture → Quick Access Drag Diagnostics…; drag sample left → right | Real GUI user action needed to confirm native drag completion |
| Finder integration | Drag a real overlay into an empty temporary Finder folder | Destination requires manual session test; no file overwrite |
| Messenger attachment | Drag a real overlay into an *unsent* message draft; verify attachment only | Never send or upload automatically; app-specific acceptance is not inferred |
| Multi-monitor placement | XCTest: laptop, left-origin external, portrait, 4 corners, connect/disconnect, small screens | Only one physical display is available in the test environment |
| Multi-monitor animation | Observe with attached external display while disconnecting/reconnecting | Automated geometry tests cannot certify visual animation |
| Accessibility/Input Monitoring/Screen Recording/Microphone transitions | XCTest injected granted→denied→granted; Settings live status refresh | Real system permission changes remain user-controlled; TCC is never modified |
| Whole app regression | `swift test -j 2` | Does not replace external-application acceptance checks |
| Release signing | `codesign --verify --deep --strict` and XPC verify | Local `AOM Dev` identity still unavailable; CI ad-hoc build only |
| DMG integrity | `hdiutil verify` and SHA-256 | Not an Apple notarized public release |

## Operational checklist

1. Open the AOM menu-bar icon → Capture → **Quick Access Drag Diagnostics…**.
2. Drag the colored test image on the left onto the drop target. Expect *PASS: drop accepted; URL and bytes match source*.
3. Optionally drag a **real capture** from Quick Access into Finder and into a *draft* attachment field of the desired messenger. Do not send the draft.
4. Plug in an external display; capture once on each monitor, move the pointer between them, and confirm each card stays on its own display. Disconnect and confirm the orphaned card relocates onscreen.
5. In System Settings → Privacy & Security, only change permissions if desired. Return to AOM's Permissions tab; status refresh should occur without manually resetting user preferences. Screen/keyboard access may require relaunch after re-grant.
6. Do not test by directly editing `TCC.db` or by changing privacy settings via elevated shell scripts.

The project does not include CleanShot Cloud or hosted sharing. The editable proprietary `.cleanshot` project format is not implemented; this QA effort concerns capture-overlay interaction parity.
