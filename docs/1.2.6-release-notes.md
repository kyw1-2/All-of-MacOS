# AOM 1.2.6 — Connected Workflows and Responsive Editing

2026-10-19 · build 2026101901 · based on the 1.2.5 hotfix at `68120e7`.

## Findings and fixes

| Finding | Result | Source |
| --- | --- | --- |
| Copy/Save/Pin Last Capture completed an automation step immediately, while the actual output was still pending; failures also appeared successful | The sequence waits for output and receives its actual success/failure. A failed save no longer opens a pin against missing output | `ActionExecutor.swift`, `CaptureActions.swift` |
| OCR Last Capture ignored the action editor's Keep Line Breaks option | Explicit true/false overrides reach recognition; absent values inherit capture settings | `CaptureActions.swift` |
| Each gesture appended an unbounded log and encoded/wrote the entire log on the main thread | Keep 2,048 recent events plus all-time per-gesture aggregates. Throttle snapshots to once per second and encode/write on a serial worker; flush on orderly exit. Legacy data remains untouched during migration | `GestureStatistics.swift`, `AppDelegate.swift` |
| Every editor keystroke synchronously encoded/validated the full preset, wrote JSON and SQLite, and created/pruned backups | Runtime bindings update immediately; saves coalesce over 250 ms and run on a serial worker. Explicit saves/loads and orderly exit drain pending changes | `AppState.swift`, `PresetManager.swift` |
| Evicted capture PNGs decoded synchronously during copy/save/OCR | Async rehydration decodes on a dedicated queue. An edit invalidates older decodes | `CaptureHistory.swift`, `CaptureActions.swift`, `QuickAccessOverlay.swift` |
| Quick Access rotation, flip, scaling and resize rendered on the UI thread; Open With synchronously exported unsaved images | Render transformations on a serial worker and await asynchronous export/open. File-info/menu availability reads metadata rather than decoding pixels | `QuickAccessImageTools.swift`, `QuickAccessOverlay.swift` |
| Newer edits could race an asynchronous transform or export | Image revisions reject stale transform results and prevent an old export being attached as the current edit's file | `CaptureHistory.swift` |
| Paste-use log saving failed on this Mac: `.atomic + .completeFileProtection` returned Cocoa 513 / EPERM when creating temporary files | Use atomic writes with existing AES-GCM encryption and owner-only file permissions. Unreadable/corrupt legacy logs are preserved while new encrypted records can be saved. Tests cover burst ordering, reload, erase, migration, unreadable legacy data and Keychain failure | `ClipboardIntelligence.swift` |

The 179-action catalog was checked for service references. This checks source reachability, not runtime operation of every hardware or system action.

## Verification

- Full `swift test -j 2`: **839 tests, zero failures, one conditional native-render skip** (set `AOM_UI_RENDER_PATH` to opt in).
- After the last transform revision adjustment: **39 focused capture/history/Quick Access tests passed**.
- `git diff --check`: passed.
- Direct filesystem experiment reproduced the old protection-option failure; encrypted log reload, legacy migration/preservation, erase and ordering tests now pass.
- The Mac was locked during native UI inspection. Interactive window/shortcut checks are not claimed; signed-bundle diagnostics and installation results are reported with the GitHub release.

An independent read-only `ask-agy` review was attempted but interrupted by its 240-second timeout; it produced no completed findings report and is **NOT_RUN**, not PASS. Deterministic tests, direct filesystem experiments and first-party diff inspection are the acceptance evidence.

A single optimized standalone benchmark on this Mac recorded the same 3,000 gesture detections and verified total/breakdown counts: 1.2.5 took **8.447 s**; the new production persistence path took **0.080 s** in the recording loop, with its final flush outside the timed interval. This isolates input-path work; it is not a whole-app speedup or a UI frame-rate measurement. The old path persisted on every input; the new path intentionally persists batches.

## Scope and remaining limits

- The first drag of an unsaved Quick Access image still uses the synchronous native file-URL drag path. Converting it to asynchronous file promises requires a separate receiving-app compatibility pass.
- Capture-history startup/index loading, external image/video imports and some print/annotation paths still do synchronous work. These have not been claimed as fixed or benchmarked here.
- The existing custom-build in-app update checker is deliberately disabled. This release uses authenticated GitHub distribution and local installation; it does not enable background updates.
- Hardware gestures, all destination apps, long recordings and multi-display scrolling are not exhaustively certified by the automated suite.

The app identifier and AOM Dev signing identity stay stable. Existing settings, clipboard history and captures are retained, with the previous installed app available for rollback.
