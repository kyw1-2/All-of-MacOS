# HomePod 전용 로컬 믹싱 / AirPlay 출력 경로

작성: 2026-10-25. 기반 커밋: `5615de8` (3.0.6 안정화 후속).

## 구현 범위

Mac에서 재생하고 macOS가 연결된 AirPlay HAL 출력 장치로 보내는 오디오에 앱별 볼륨·음소거·앱 EQ·전체 EQ·앱/전체 부스트를 적용한다. `HomePod / AirPlay effects`는 기본 켜짐이다. 끄면 기존 AirPlay 직접 재생으로 돌아가며 효과 설정은 보존한다.

```text
앱별 CoreAudio process tap (capture-only aggregate)
    → 앱별 PCM 큐 / 48 kHz 변환 (AirPlay: 기본 80 ms, 큰 패킷에 적응)
    → 앱별 gain / mute / EQ / master EQ / boost
    → 48 kHz stereo 로컬 믹스 (별도 큐, 10 ms 블록)
    → 제한된 송신 PCM 큐 (기본 150 ms, HAL 버퍼 크기에 적응)
    → 출력 전용 AUHAL 한 개 / 연결된 장치
    → macOS AirPlay 전송
    → HomePod
```

`AirPlayOutputRenderer`는 macOS가 이미 연결한 장치를 사용한다. 자체 AirPlay 2/RAOP 프로토콜, 새로운 가상 오디오 드라이버, Rogue Amoeba ARK 바이너리 통합은 아니다. 기존 로컬 AVAudioEngine 그래프와 독립된 출력 전용 AUHAL을 만들며 입력은 명시적으로 비활성화한다. AirPlay 장치를 AVAudioEngine에 직접 붙이지 않는다.

## 수명과 복구

- 송신기 초기화·정지·폐기는 메인 스레드 밖에서 수행한다. 동일 작업 큐로 폐기와 재생성을 순서대로 처리한다.
- 실제 HAL 출력 콜백과 버퍼 소비가 확인되어야 준비 완료로 전환한다. 그 전에는 새 muting tap을 만들지 않는다. 송신 시작 확인은 최대 15초 동안 기다린다.
- 앱 추가·종료, EQ·볼륨·부스트 변경은 소프트웨어 소스/매개변수만 변경한다. 앱이 잠시 조용해져도 송신기를 다시 열지 않는다.
- 로컬 믹서는 네트워크 소비 속도나 메뉴의 메인 런루프에 종속되지 않는다. 송신 콜백은 미리 할당한 PCM 큐만 읽는다. 콜백에서 DSP, 장치 재구성, 메모리 할당, 대기 잠금을 실행하지 않는다.
- 장치 샘플레이트에 맞춘 선형 보간과 최대 ±0.5%의 완만한 클록 보정을 사용한다. 끊긴 버퍼는 다시 채우고 20 ms 페이드로 재개한다. 지연된 믹싱 타이머는 과거 블록을 무한히 따라잡지 않는다.
- 출력 콜백이 3초 이상 중단되거나, 실제 포맷/장치 구성이 변경되면 실패 상태를 알리고 원래 재생을 복원하도록 앱 캡처를 해제한다. 값이 같은 중복 장치 알림만으로 연결을 파괴하지 않는다.
- 출력 중인 앱에서 캡처 콜백이 5초 이상 끊겨도 해당 앱의 캡처를 해제한다. 무음 샘플 자체를 오류로 판정하지 않는다.
- 실패한 원격 출력은 자동 재시작을 반복하지 않는다. `Reconnect Audio` 또는 처리 모드 재설정으로 복구한다. 캡처 실패도 별도로 기억하여 탭 생성/삭제로 발생한 process-list 알림이 재시도 루프를 만들지 않게 한다.
- 다른 출력으로 이동한 뒤 사용하지 않는 송신기는 해제한다. 두 출력에 잠시 등록되는 경로 이동에서는 같은 앱의 DSP 버퍼를 동시에 렌더링하지 못하도록 보호한다.
- 기존 로컬 출력 강제 복귀 옵션은 저장값을 지우지 않고 HomePod 효과 모드가 켜진 동안 중단한다. 기본 출력이나 HomePod 선택을 몰래 변경하지 않는다.

## 사용자 표시

큰 오디오 화면과 작은 믹서에 같은 HomePod 효과 토글을 제공한다. 준비 중, 처리 중, 직접 재생, 실패를 구분하고 재연결 버튼을 제공한다. 실제로 지원하지 않는 HomePod 하드웨어 볼륨을 가짜 소프트웨어 슬라이더로 표시하는 제한은 유지한다. 앱별 볼륨은 믹싱 경로에서 적용된다.

## 근거와 한계

공개 API의 장치 지정·입출력 scope 및 AUHAL 샘플레이트 제약은 Apple 문서를 참고했다:
- [TN2091 — HAL Output Audio Unit](https://developer-mdn.apple.com/library/archive/technotes/tn2091/_index.html)
- [Audio Unit Output Subtypes](https://developer.apple.com/documentation/audiotoolbox/1584148-audio-unit-output-subtypes?language=objc)

이전 SoundSource REA 자료는 장기 유지되는 캡처·출력 객체 및 부스트 처리에 대한 참고 자료다. 심볼이나 단순 setter만으로 SoundSource의 AirPlay 전송 방식이나 안정성이 검증되었다고 주장하지 않는다. 이번 전용 경로는 AOM 자체 구현이다.

기본 로컬 추가 버퍼는 약 230 ms이며 실제 장치의 큰 패킷과 버퍼 크기에 따라 늘어난다. HomePod 자체 전송 지연은 별도다. 다른 앱의 영상 타임라인을 강제로 이동하거나 A/V 동기화를 보장하는 구현은 포함하지 않는다.

HomePod 자체 재생, 다른 기기에서 HomePod로 직접 전송하는 오디오, Mac PCM 캡처를 우회하는 원격 핸드오프/보호된 콘텐츠는 이 경로의 처리 대상이 아니다. 기존 로그의 HomePod/AirPlayXPCHelper 외부 Pause 명령을 차단하거나 재생 명령으로 덮어쓰지도 않는다.

## 검증 상태 및 인계

사용자 요청에 따라 이번 변경 후 빌드, 테스트, 실행, 설치, 실제 HomePod 재생 검증은 수행하지 않았다. 구현을 완료했다는 뜻이며, 컴파일 성공이나 HomePod 실기 안정성·음질·영상 동기화까지 확인했다는 뜻은 아니다. 기존 릴리스의 버전 번호와 설치본은 변경하지 않는다.

사용자가 이어서 확인할 항목: Chrome/Safari 재생 지속, 앱별/전체 EQ·부스트·볼륨·음소거, HomePod mono/stereo pair, 44.1/48 kHz 장치, 장치 전환·재연결·잠자기, 네트워크 중단 시 직접 재생 복원, 직접 재생 토글, 부하 상태에서 영상 동기화 및 추가 지연.
