# All of MacOS — local signing: AOM Dev

All of MacOS uses an independent, **self-signed Code Signing certificate** named **AOM Dev**. This is suitable for personal testing and stable local permissions; it is not a paid Developer ID identity and does not provide Apple notarization.

## One-time Keychain Access setup

1. Open **Keychain Access** on the Mac.
2. Choose **Keychain Access → Certificate Assistant → Create a Certificate…**
3. Name it **AOM Dev**.
4. Set Identity Type to **Self Signed Root**.
5. Set Certificate Type to **Code Signing** (not a generic certificate).
6. Create it in the login keychain, following any native confirmation prompts.

Apple's guide: https://support.apple.com/guide/keychain-access/create-self-signed-certificates-kyca8916/mac

The local build and XPC scripts default to **AOM Dev**. The shared resolver selects its SHA-1 fingerprint from `security find-identity -v -p codesigning`, so duplicate untrusted certificates with the same name do not make `codesign` ambiguous. If more than one valid AOM Dev identity exists, set `ALLOFMACOS_SIGN_ID` to the intended fingerprint. An explicit fingerprint must also belong to a valid identity named exactly **AOM Dev**; unrelated signers are rejected. The application passes the resolved fingerprint to the XPC helper so both use the same certificate. GitHub Actions may explicitly use `ALLOFMACOS_SIGN_ID=-` for **ad-hoc CI builds only**.

Build the current source with `./build-and-sign.sh`. It assembles and verifies an isolated app under `build/`; installing it remains a separate step after the build and signature checks succeed.

## Verified status

On 2026-10-12, the login keychain contained several AOM Dev certificates. Five had matching private keys and Code Signing usage, but were excluded from valid identities with `CSSMERR_TP_NOT_TRUSTED`. The existing certificate with SHA-1 `7A0B14B650E6F6CBA01E6CA97D0AD0EE8A74699E` was trusted in the **user domain for Code Signing only**. No certificates or private keys were deleted, and no SSL or system-wide trust was added.

That identity now appears in `security find-identity -v -p codesigning`. Certificate verification with the Code Signing policy, signing and strict verification of an isolated Mach-O smoke binary, execution, and repeat signing all succeeded. This confirms the identity is usable; each new application build still requires its own build and signature verification before installation.

The existing `All-of-MacOS-1.0.1.dmg` is an older build and must **not** be represented as newly signed with AOM Dev.
