# All of MacOS — local signing: AOM Dev

All of MacOS uses an independent, **self-signed Code Signing certificate** named **AOM Dev**. This is suitable for personal testing and stable local permissions; it is not a paid Developer ID identity and does not provide Apple notarization.

## One-time Keychain Access setup

1. Open **Keychain Access** on the Mac.
2. Choose **Keychain Access → Certificate Assistant → Create a Certificate…**
3. Name it **AOM Dev**.
4. Set Identity Type to **Self Signed Root**.
5. Set Certificate Type to **Code Signing** (not a generic certificate).
6. Create it in the login keychain, following any native confirmation prompts.

Apple's guide: https://support.apple.com/guide/keychain-access/create-self-signed-certificates-kyca8916/mac

The local build and XPC scripts now default to **AOM Dev** and reject unrelated signers. GitHub Actions may explicitly use `ALLOFMACOS_SIGN_ID=-` for **ad-hoc CI builds only**.

Once the proper `AOM Dev` signing identity is recognized, `scripts/package-aom-dev.sh` re-signs an isolated copy of the previously built 1.0.1 app, verifies the new signature on both application and XPC helper, and produces a new `All-of-MacOS-1.0.1-AOM-Dev.dmg` in Downloads. It will not overwrite the older DMG.

## Verified status

The independent scripts are configured to use **AOM Dev**. A generic certificate with that name was created using certtool; however, `codesign` still returns **no identity found**. The certificate must be created with **Certificate Type: Code Signing** in Keychain Access.

The existing `All-of-MacOS-1.0.1.dmg` is an older build and must **not** be represented as newly signed with AOM Dev.
