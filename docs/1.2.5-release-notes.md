# AOM 1.2.5 — Clipboard, Capture & Automation Responsiveness

2026-10-18 · build 2026101805 · based on 1.2.4 / b906670cde5176899c2bf6da3cb5055d0694e521.

## Changes

### Clipboard (Paste comparison)

- Poll every 150 ms with 25 ms tolerance in common run-loop modes, replacing a 600 ms/default-mode timer. Collection continues during menu tracking. Polling is still sampling and cannot guarantee retention of every faster-than-poll copy.
- Classify/hash incoming copies on a separate serial user-initiated queue, rather than behind encryption/writing of the full history archive.
- Preserve copies made during initial archive loading and locally created snippets that would previously be overwritten when loading finished.
- Publish duplicate-copy updates once, rather than remove/insert notifications, and prune obsolete image-index attempt IDs with deleted history.
- Move Paste Stack payload reads outside the consuming keyboard-event-tap callback. Bound queued paste requests and hand off a restarted stack session after the old worker exits.
- Direct shelf paste uses PID-targeted private-state events, without waiting for Command/Shift to be released. Focus, Accessibility, target lifetime and intervening clipboard changes are checked before posting. The 180 ms stack-consumer settling interval remains deliberately unchanged.
- Decode UTF-16 and RTF/RTFD-only text for search/plain-text paste while retaining the original rich payload. Capture WebP/GIF representations as image entries; previews/OCR use their first image frame.
- Parse date-filter values once per search query rather than for every history entry.
- Clear timed pause state on every resume path, including menu/shortcut toggles.
- Reject out-of-range shortcut preference values rather than trapping during integer conversion.

### Capture (CleanShot X comparison)

- Screenshot and text-capture workflow steps report completion after output/history is ready. A following copy/OCR/annotation step no longer starts against the previous capture. Cancellation or a failed delivery returns failure to the sequence runner.
- Image encoding and ordinary save operations run on a serial background queue. Quick Access copy, save, copy-file, reveal, annotate, pin and Save All await that work without blocking the UI thread; repeated media clicks are serialized and auto-close pauses while work is pending.
- Build clipboard representations before replacing the pasteboard, then write them as one item. PNG replaces the unconditional uncompressed TIFF compatibility payload, reducing avoidable history-size failures for Retina screenshots.
- Save new screenshots with exclusive file creation; concurrent same-name saves use suffixes instead of overwriting a capture.
- Capture All Displays applies the configured output path to each display, including overlays, copy and annotation. Copy mode leaves the first display on the clipboard; it is not a multi-image combined clipboard payload.
- Failed automatic copy/save retains a recoverable Quick Access card and reports failure. Text/QR delivery now checks whether the clipboard write succeeded before announcing success.
- Explicit Quick Access imports work when automatic overlays are disabled; restoring the same capture reuses its existing overlay.

### Automation (BetterTouchTool comparison)

- Remove UI-thread sleeps from synthesized keyboard pairs and mouse-click sequences. Dictation's two-press spacing uses an asynchronous callback.
- Honor ignore/restart/parallel policy while a trigger is waiting for its initial delay, with a four-invocation limit for parallel starts.
- Stop All also invalidates delayed trigger starts. Deleting/disabling/editing a trigger or changing activation groups invalidates its pending starts and normal sequences, not only held-repeat loops.
- Re-resolve app/group applicability before a delayed trigger executes. Do not use a stale binding in a different application context.
- Cancellation reaches pending text-input chunks, custom scrolling and the delayed Paste String key dispatch. Paste String checks focus and intervening clipboard changes and targets the original process.
- OCR Last Capture reports completion after recognition and clipboard delivery, so subsequent workflow actions can use its output.

## Comparison coverage and remaining differences

This is a source-path review against official feature descriptions, not a runtime parity certification or an exhaustive hardware/device matrix. Existing features below were found in source; their actual operation was not tested in this release.

| Area | AOM source paths / existing capability | Remaining difference or boundary |
| --- | --- | --- |
| Paste history, pinboards, filters | ClipboardStore, ClipboardPanel, ClipboardSearchQuery; local history, multiple selection, editable clips, app/type/date/board filters | Retention is bounded by settings; no iOS/iPadOS companion, iCloud sync or shared team pinboards |
| Paste image search and suggestions | TextRecognitionService, ClipboardIntelligence; local OCR and opt-in local-model suggestions | No claim of equivalent ranking/recognition; background OCR waits while the shelf is open |
| Paste Stack and direct paste | ClipboardStackPasteMonitor, ClipboardPanel | Destination apps consume clipboard data asynchronously; real-app compatibility and timing were not measured |
| CleanShot screenshots and scrolling | ScreenCaptureService, ScrollingCaptureService, SelectionOverlay | Scrolling quality, fixed headers, cross-display scaling and application-specific capture not exercised |
| CleanShot markup and pinning | AnnotationEditor, AnnotationDocument, PinnedScreenshot | AOM has its own project format; editing/rendering fidelity not measured |
| CleanShot recording and Studio | ScreenRecordingService, RecordingExportEditor, AOMStudioRenderer | Audio/video sync, recovery, camera overlays and export quality not exercised; not full Studio feature parity |
| CleanShot Quick Access | QuickAccessOverlay, CaptureCoordinator | Save As, first unsaved drag export, some external-open paths and image transforms still have synchronous work; full history loading also remains synchronous |
| CleanShot Cloud | No corresponding hosted collaboration backend | No cloud account/share-link service, comments, team administration, SSO/SCIM or automatic cloud transcripts |
| BTT trigger/sequence engine | TriggerResolver/Gate, ActionExecutor, ActionControlFlow; gestures, keyboard/mouse, app/groups, conditions, named triggers, scripting | Hardware/timing behavior not exercised; no assurance of every BTT action/trigger equivalent |
| BTT device ecosystem | Existing trackpad/keyboard/normal mouse and system signals | No Magic Mouse touch-surface driver, Touch Bar, Stream Deck, MIDI, gamepad, Siri Remote or BTT Mobile equivalents |
| BTT floating menus / launcher | AOM command palette and HUD | Not a general BTT floating-widget/menu or launcher engine |
| Cancellation boundary | Pending trigger starts, runner steps, typing, custom scrolling and Paste String dispatch | Already-started external scripts, captures, OS app launches and some system actions are not forcibly undone |

## Build and installation policy

The user explicitly requested commit, GitHub release and local installation without verification. The repository does contain an automated `swift test` suite (55 files under `AllOfMacOSTests`, wired into `.github/workflows/tests.yml`), but it was not run for these commits: no automated tests, UI tests, benchmarks, hardware exercises, independent review or runtime smoke test were performed for this release. Only compilation, signing and packaging needed to produce the application are performed. CI is skipped for these commits. Build completion does not establish functional correctness or measured speedup. Existing settings and history are preserved; the previous app is retained for rollback.
