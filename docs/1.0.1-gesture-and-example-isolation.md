# All of MacOS — Gesture & Text Configuration Audit

## Code versus user configuration

- The finite list of recognized trackpad gesture **types** is defined in `Models/TriggerType.swift`. This is a gesture-recognition capability catalog, **not** preinstalled mappings.
- `Trigger` records a gesture input and its user-selected `TriggerAction` array. A newly constructed trigger has **no actions**.
- `Preset` initializes with **zero triggers**. Live bindings are saved under `~/Library/Application Support/AllOfMacOS/master_preset.json`, with `trackpad-v1.sqlite` as a redundant persisted store; no source-code defaults install personalized bindings.
- `Type Text` uses each action's optional `ActionParameters.text` value, entered via the Configuration Panel's `TextEditor`, stored in the preset and consumed at execution time. Neither the code nor the distributed example supplies a personal text payload.
- `GestureReplaySuite` uses simulated touch events and a test callback; the gesture name used as its test value is **not typed into other applications**.
- No KakaoTalk mapping is compiled into the application. The old optional repository example was replaced with `Examples/Disabled-Show-HUD.json`, which is **disabled** and only displays an in-app HUD if deliberately imported and enabled.
- Existing user presets are **not** cleared or rewritten by the audit. All of MacOS retains its own application profile and data directory.
- Dedicated native triggers and built-in macOS shortcut defaults may still exist for app features such as capture and clipboard; those are platform capability controls, not personalized gesture-action bindings.

## Regression coverage

`PresetConfigurationIsolationTests` verifies a fresh preset contains no user bindings, editable Korean/emoji text and app selection round-trip through `PresetCodec`, recognized trackpad inputs serialize without baked-in actions, and the disabled sample cannot launch or type into another app.
