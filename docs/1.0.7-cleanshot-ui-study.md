## Implementation interpretation

The existing AOM surfaces corresponding to these findings are `Views/QuickAccessOverlay.swift`, `Views/AnnotationEditor.swift`, `Models/AnnotationDocument.swift`, `Views/PinnedScreenshot.swift`, `Views/CaptureSettingsView.swift`, and the capture/recording services. The useful design direction is a compact tool strip with contextual properties, a prominent image canvas, and screenshot-overlay actions that remain distinct from pinned-image controls. This is an implementation interpretation, not a recovered CleanShot source design.

Raw nib frames describe archived preference controls only. They must not be presented as current screen measurements. Similarly, packaged placeholder labels and slider values must not be treated as the user's live configuration. UI changes should preserve AOM capture identity, underlying image data, export failure handling, and existing gesture/clipboard storage.

## Remaining validation

Runtime inspection must independently establish annotation tool grouping, toolbar/canvas spacing, hover actions, overlay size, screen-edge placement, focus, double-click behavior and compact-window behavior. Recording and selection visuals need their own checks. Tests and installation verification belong to the implementation run and are not asserted by this static ledger. CleanShot Cloud, proprietary project formats, licensing and premium integrations were outside this UI study.
