## New deterministic and integration checks

`AutomationExpansionTests`: menu action/widget persistence and duplicate/invalid import rejection; streaming MIDI/running-status/realtime/zero-velocity Note Off; raw original-allocation MIDI packet traversal with multiple and >256-byte packets; MIDI/gamepad/HID value/device filters and Codable/source registration; script failure/status/truncation; AX selector ambiguity avoidance; seven image-matcher tests (exact/noisy/transparency/budgets/cancellation/raster orientation/display-coordinate conversion/invalid configuration); overnight weekday and inclusive date windows; same-day-of-month scheduling regression; actual filesystem missing-file creation and repeated atomic replacements.

Hardware monitors use public CoreMIDI, GameController, IOHID, CoreWLAN/IOKit APIs. Tests do not imply that a device was attached. Release-level results and any test failures belong in the final release validation log.

## BTT JSON subset import boundary

`Services/BTTPresetImport.swift` accepts a flat selected-trigger object or array (1–500 triggers, 1–64 actions/trigger), at most 4 MB, depth 32 and 30,000 JSON values. It preserves key-down/key-up phase and known shortcut modifier bits. Shortcut action264 accepts descending supported left-modifier physical keycodes followed by one non-modifier keycode; right/side-specific modifiers, onlyDown/onlyUp, current-modifier inclusion and low-level injection are rejected. Explicit false flags and empty additional-data objects are harmless; unsupported nonempty additional data (including named-call variables) rejects the trigger. Unknown fields are rejected rather than silently ignored, except the explicitly listed UUID/order/descriptive metadata.

`BTTPresetImportTests` verifies all six simple action IDs, action ordering, key-up mapping, named calls, shortcut conversion and rejection, whole-trigger rejection for action/condition/scope/event semantics, independent skip reporting, malformed numeric fields, byte/depth/count/wrapper limits and a disabled additive merge preserving the existing preset. GUI review and actual third-party exported file acceptance remain separate from these tests. Existing native AOM codecs are checked before the BTT adapter; importing BTT never replaces the preset or executes actions. Imported BTT triggers are global; names/collisions and unresolved named targets require review before enabling.

Mapping evidence is the BTT6.957 bundled `trigger-definitions.mdx` / `action-definitions.mdx` recorded on Oracle under `/data/academic-workspace/reports/aom-128-csx-501-btt-6957-20261020/evidence/`. Only documented numeric IDs/fields were mapped; no vendor implementation source was copied.
